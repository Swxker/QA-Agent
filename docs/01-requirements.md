# 需求与验收标准

## 用户与目标

运营人员输入主题、预算、截止时间，系统利用合成素材与费用耗时表，在约束内生成并保存内容活动方案。运行入口为 CLI，模型供应商为 DeepSeek。

## 范围

包括素材检索、脚本生成、权威估算、保存、计划调整、步骤状态、费用账本、重复执行保护和失败续跑。不包括真实素材采购、内容发布、前端页面或多机部署。工具、素材及费用为合成数据；真实模型费用另记 token 用量。

## 输入与输出

输入：非空主题；非负且最多两位小数的预算；带时区截止时间。预算/截止时间可缺失，返回可续跑 `needs_input`。格式错误退出 2，不伪造成业务成功。

输出：计划与版本、步骤与依赖、工具结果和产物 ID、累计费用、完成估算与缺口、方案或未完成原因。CLI 标准输出 JSON；可导出方案 JSON/Markdown 和 Trace JSONL。

## 完成判据

必要资料完整、存在可用脚本、最新估算对应该计划和费用状态、完成总费用不超预算、剩余模拟工作能在截止时间内完成、保存事务提交成功，模型再通过 finish 检查。仅生成脚本或提出计划不算完成。

## 必须验收

| 要求 | 判据 |
| --- | --- |
| 正常 | 方案保存，状态 completed，账本正确 |
| 缺预算/时间 | needs_input，零模型与工具调用 |
| 工具失败 | 失败 attempt 不标成功，后续策略可观察 |
| 超预算 | 观察不可行报价后重选并重新估算，或返回明确缺口 |
| 重复执行 | 相同请求返回已有任务，工具次数、账本与方案数不增加 |
| 续跑加分项 | 已成功脚本保留，仅恢复必要步骤 |
| 有界执行 | 达到累计决策/工具次数上限后明确未完成 |
| 真实模型循环 | 模型工具选择→执行→工具观察→模型下一动作 |

必须提交至少三组实际输入、输出及记录，覆盖全部验收点。至少两条真实模型路径体现不同工具结果造成的动作变化。离线 Mock 记录只证明流程，不证明最后一项。

## 验收材料

验收材料包括可执行测试、合成素材与规则、实际输入输出及 Trace。已完成 51 项自动测试、14 个离线场景和 14 个真实模型场景；两条核心真实路径分别展示超预算重规划与保存失败恢复。具体结果及限制见 [评估报告](03-evaluation.md)。
