# AI 辅助使用说明

本项目使用 AI 辅助完成设计、开发、测试和文档整理。个人工作主要集中在需求与方案确认、模型选型、验收范围界定、验证方式把关和真实模型验证条件准备；代码与测试的具体实现主要借助 AI 完成。

## 个人贡献

- 明确业务目标和验收范围，将预算核算、步骤依赖、工具失败、重复执行及结果保留作为核心检查点；确认采用 CLI 交付和原生 Python 工具循环方案。
- 选定 DeepSeek 作为真实模型供应商，并准备 API 访问配置，使验证从离线 Mock 扩展到真实模型调用。
- 将真实模型的“选择动作—执行工具—观察结果—调整下一步”作为验证重点，推动完整流程实测；区分离线流程测试与真实模型决策证据，避免仅凭 Mock 测试通过判断项目达标。
- 确认交付材料应包含可复制命令、实际输入输出和 Trace，并要求区分 AI 辅助范围、个人贡献与实际验证结果。

## AI 辅助范围

| 环节 | 辅助内容 |
| --- | --- |
| 需求与设计 | 拆解输入输出、预算与时间规则，设计工具接口、状态、依赖及幂等机制 |
| 代码实现 | 生成并修改 CLI、DeepSeek 适配器、工具循环、SQLite 存储和离线 Mock |
| 测试与运行 | 编写自动测试、故障注入与费用审计脚本，执行离线及真实模型验收 |
| 问题改进 | 根据真实运行中的持续重试问题，修改提示和失败反馈，执行回归验证 |
| 文档与数据 | 整理项目说明、评估结果和复盘，生成合成素材、规则与示例输入 |

AI 参与了主要代码和测试的编写，也执行了自动化验证。个人贡献以需求与方案确认、验证方式和验收要求的把关，以及运行条件准备为主。

## 验证结果

- **自动测试：51 项通过。** 覆盖预算、依赖、状态、工具故障、幂等、并发锁、续跑、模型接口和 CLI；见 [测试结果](../examples/test-results-latest.txt)。
- **离线流程：14 个场景通过。** 用于验证流程和工程约束，不作为真实模型决策能力的证明；见 [离线总表](../examples/mock/summary.json)。
- **真实模型：14 个验收场景全部符合预期。** 使用 DeepSeek 实际调用，覆盖超预算重规划、失败恢复、重复执行和续跑；见 [真实总表](../examples/real-full/summary.json)。
- **独立费用审计：全部通过。** 核对费用账本与 Trace、收费唯一性、预算和调用上限，以及重复执行与续跑的产物一致性；见 [审计结果](../examples/real-full/audit.json)。

首次完整真实验收中，续跑场景因反复重试导致调用额度不足。原始记录保留；改进错误反馈和提示后，重新执行完整验收并通过。具体过程见 [评估报告](03-evaluation.md)。

## 使用边界

运行记录来自实际执行，保留失败尝试；合成 HTTP 响应测试、离线 Mock 和真实模型记录分别标识。Trace 只记录动作、工具结果及简短决策依据，不包含模型内部思维过程。密钥不写入源码和运行证据。
